# Eye of the Soul: builder report (2026-11-25)

For merging into `specs/soulfire.md` ("Eye of the Soul: phasing": status becomes built) and the Reworked Mobs player page. Governed by C1 (B15: no new blocks; this is an item and an effect).

## What was built

- **Item `bubbas_reworked_mobs:eye_of_the_soul`** ("Eye of the Soul"): shapeless soul blaze powder + ender pearl (`recipe/eye_of_the_soul.json`, recipe-book unlock generated by `tools/recipe-unlocks.py`). Stacks to **16**, **1 s use cooldown** *(builder)*. Right-click: uses one up, starts **Phasing for 5 s** (100 ticks), soul particles (vanilla `soul`) and two sounds (soul escape + ender eye death, low pitch) *(builder)*. Using another while Phasing tops it back up to 5 s (vanilla effect merging). In the Reworked Mobs creative tab after the Soul Fire Charge.
- **Mob effect `bubbas_reworked_mobs:phasing`** ("Phasing"): neutral, colour #0B5F63 *(builder)*, no swirl particles, icon shown. It is the whole state: collision, climbing, blindness and burning all read it.
  - **Can't be cleared early**: Fabric API's `ServerMobEffectEvents.ALLOW_EARLY_REMOVE` refuses its removal for milk (26.3 milk is the `clear_all_status_effects` consume effect -> `removeAllEffects`), Totem of Undying, honey/other `remove_status_effects`, and any mod calling `removeEffect`/`removeAllEffects`. **Exception *(builder)*: commands** (`/effect clear`) can still remove it, as an admin escape hatch. Other effects are still cleared by milk.
- **Phasing = scaffolding rule on every breakable block** (destroy speed != -1), for the Phasing **player** only (other entities given the effect by command just burn): the block's own collision shape counts only while the player is above its top and not sneaking, else nothing (vanilla `ScaffoldingBlock.getCollisionShape`, using vanilla `CollisionContext.isAbove`/`isDescending`). Bedrock, barriers, end portal frames, command blocks, etc. stay solid.
  - Using the block's own shape (not a full cube) means you stand on slabs, fences and stairs at their real height.
  - **Climbing**: a Phasing player whose box overlaps a passable block's shape counts as on a climbable (`LivingEntity.onClimbable`), so: hold jump to climb at 0.2 blocks/tick (ladder/scaffolding speed), horizontal speed capped at 0.15 blocks/tick inside blocks, fall speed capped at 0.15; sneaking sinks (treated like scaffolding, where sneaking doesn't hold you on the ladder).
  - Note for the spec: "inside a block with no input you slide down slowly, as in scaffolding": with the vanilla rule reused exactly, you slide down only until your feet reach the top of a block below you, then stand there (as in a scaffolding tower). Sneak to keep sinking.
- **Server side**: the server simulates the same collision (it has the effect), and its anti-cheat "moved into a new block" check (`ServerGamePacketListenerImpl.isEntityCollidingWithAnythingNew`) treats passable blocks as scaffolding does (no collision), so moves into walls aren't rubber-banded. The block placement check is left vanilla (a Phasing player can't place blocks overlapping mobs).
- **No shove-out**: vanilla's client push-out (`LocalPlayer.moveTowardsClosestSpace`) uses the same collision, so it does nothing while Phasing and works as normal once Phasing ends. **No suffocation damage while Phasing** (`in_wall` damage cancelled); vanilla suffocation after it ends.
- **Cost**: Soulfire burning for the whole Phasing time (the existing Soulfire rules: 1.5 a second to the living, totems skipped), refreshed every tick so it can't be put out by water while Phasing and ends with it. **Soulguard: no burning at all.** (New `SoulBurning.igniteForTicks`.)
- **Blindness that can't be overridden** (client): a fog environment of its own, keyed to the Phasing effect (not a Blindness effect), put first in vanilla's fog list, so Night Vision, milk or other mods can't lift it: **vanilla Blindness's fog (5 blocks; full fog from 5, clear only within 1.25)**, fading back in over the last second like Blindness. **Soul-tinted**: the fog colour is a near-black soul teal (0, 0.045, 0.05); its red channel is 0, which is what stops vanilla's Night Vision fog brightening from lifting it. The sky is hidden (as with Blindness/Darkness).
  - **Blindness vs Darkness: chose Blindness-style.** Screenshots of both (see below): with Darkness-style fog (15 blocks, start at 11) the whole lit room and the stone cube read clearly from inside and outside; Blindness-style hides everything past ~4 blocks.
  - **X-ray check**: with the eye inside stone, vanilla's in-wall overlay (the block's texture, near-black) covers the whole screen; nothing behind it shows, with or without Night Vision, either fog style. Chunk culling therefore doesn't expose anything. The overlay is vanilla's and untouched (it only skips `noPhysics` players, which Phasing players are not).
  - The first-person fire overlay shows Soulfire's blue flames on top (it's real: the player is burning).

## Numbers (`soulfire/SoulfireTuning`)

`PHASING_TICKS = 100` (5 s), `EYE_STACK_SIZE = 16`, `EYE_COOLDOWN_SECONDS = 1.0`, `PHASING_COLOR = 0x0B5F63`; fog distance `PhasingFogEnvironment.DISTANCE = 5` (vanilla Blindness). Speeds are vanilla's climbable ones (0.2 up, 0.15 cap).

## Tests

- Milestone `PhasingGameTest` (8, all pass): `eyeIsCraftedAndStartsPhasing`; `walksThroughStoneNotBarriers` (through a stone wall standing on the floor, stopped by a barrier wall; a player without Phasing stopped by the stone); `sinksThroughFloorWhileSneakingBedrockHolds` (stands on stone, sinks while sneaking, lands on bedrock); `climbsThroughCeilingWhileJumping` (climbs up through stone and stands on top; a barrier ceiling holds); `serverAcceptsMovesIntoStone` (the server's move check, called directly: rejects stone without Phasing, accepts it with, still rejects bedrock); `phasingBurnsWithSoulfireUnlessSoulguard`; `milkDoesNotClearPhasing` (also `removeEffect`); `endingInsideStoneSuffocates` (no damage while Phasing, suffocation after, not moved).
  - How movement is tested: test players are server players, which don't run their own movement, so the tests call the player's own physics (`LivingEntity.travel`, the same code the client runs for its player; jump as `aiStep` does) tick by tick. That exercises the real collision, climbing and sinking; the client-to-server packet path itself isn't simulated, its check is tested directly. Test players' connections aren't ticked by the server, so the burning/suffocation tests tick the players themselves (`doTick`) and mark the "client" loaded so they can be hurt.
  - Test-only mixin: `test/mixin/MoveCheckInvoker`.
- Full `./gradlew :bubbas_reworked_mobs:build -PmilestoneTests`: all pass (one run had `boss_piglin_game_test_heads_for_alit_portal` time out under full-suite load; it passed alone twice and in the next full run: flaky, unrelated).

- Phasing only changes collision for players; a mob given the effect by command just burns.
- Other mods that bypass the effect API (`removeEffectNoUpdate` directly) could still remove it; and shader packs or mods that replace vanilla fog could lift the blindness (the in-wall overlay still hides x-ray from inside blocks).
- Riding while Phasing: the vehicle collides normally (only the player's own collision changes).
- No test of the third-person camera inside blocks (vanilla pulls the camera in before walls).
