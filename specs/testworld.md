# Test world (spec)

A superflat world with a station for every playable feature, so the owner can try everything in one place (A3 ownerSteersByPlay).

## Pristine vs playable

- **Pristine:** `testworlds/bubba-test-world/` in the repo. Built only by `tools/build-testworld.py`, never opened in a game, committed to git. Holds a `BUILD_INFO.txt` with the date and the mod versions it was built with.
- **Playable:** `tools/install-to-modrinth.ps1` copies the pristine world into the Modrinth profile's `saves/` as "Bubba Test World". The owner plays that copy; nothing in it flows back to the repo.
  - The copy is made when it's missing. If the pristine world is newer than the copy, the script says so and leaves the copy alone; `-ResetWorld` writes over it with a fresh copy (owner: no old copies are kept; a reset also deletes any "Bubba Test World (old ...)" backups from earlier versions of the script).
  - The install also copies the owner's own settings, see `tools/sync-minecraft-settings.ps1`.

## How it's built

- A real headless Fabric server (Fabric's server launcher, Fabric API and the repo's built mods, the same downloads `tools/packtest.py` uses) creates a fresh superflat world and runs a builder datapack's function that places every station with commands, then saves and stops. Anything that fails is reported and fails the build.
- `level.dat` is then adjusted so it opens in singleplayer as intended: name "Bubba Test World", creative, cheats allowed.
- Rebuild whenever a feature changes what should be tested; the station list below is updated in the same change.

## World settings

Superflat (bedrock, dirt, grass), plains. Creative, cheats on. Time frozen at night (woken undead burn in daylight), clear weather locked, invisible light blocks so stations are lit. No random mob spawning (stations spawn what they need). Player spawn at the hub, facing the station signs.

## Stations

Each station has a sign naming it and saying what to try.

## As built

- **Run:** `python tools/build-testworld.py` (builds all seven mods (`MODS`: Reworked Mobs, Extra Recipes, Infused Gems, Reworked Beacons, Totems & Artifacts, Reworked Mining, World Tweaks) with Gradle first, and loads Stormie's Spiders, which Reworked Mobs requires, from the Gradle cache; `--no-build` uses the current jars, `--verify-only` re-checks the pristine world, `--keep` keeps `build/testworld-server/` and `build/testworld-verify/` with a `console.log` of every reply, `--verbose` prints every command). About 30 s on the owner's PC with Gradle up to date (server start 7 s, build 13 s, verify ~8 s); the first run also downloads the Fabric launcher, Fabric API and the game libraries.
- **Server:** reuses `tools/packtest.py`'s download helpers and cache (`build/packtest/cache`, SHA-512 checked). `server.properties`: `level-type=minecraft:flat`, `generator-settings={"layers":[bedrock 1, dirt 2, grass_block 1],"biome":"minecraft:plains","lakes":false,"features":false}` (the 26.3 `FlatLevelGeneratorSettings` JSON; ground top at y=-61, stations stand on y=-60), `generate-structures=false`, `gamemode=creative`, `difficulty=normal` (peaceful would delete woken undead).
- **Builder datapack:** `testworlds/builder/` (namespace `bubba_testworld`, format 121; `tools/pack.py check` covers `testworlds/` packs). `build.mcfunction` calls one function per station: `setup`, `hub`, `crafting`, `tower`, `arena`, `loot`, `graveyard`, `gems`, `grounds` (which calls one `grounds_*` function per testing-grounds area, including `grounds_beacons` (beacon yard, poison trap, bell lane, light rings) and `grounds_paired` (paired beacons room and spawn test boxes)), `cairn` (the preview), `creepers`, `cairns`. **The `grounds*.mcfunction` files are generated** by `tools/testworld-grounds.py` (owner: after a regenerate from an old scratch copy undid the "Gem Power" rename): edit the script, not the generated files, then run `python tools/testworld-grounds.py` and `python tools/build-testworld.py`. Effect names on signs come from Infused Gems' `en_us.json` (falling back to vanilla's lang in `build/mcsrc/`) and the level label ("Gem Power") from the gem item's name pattern, so a rename in a mod reaches the signs on the next generate. Sign-only wording ("perfect set", the Gem Power V twin lines) is in named constants at the top of the script, and every sign line is checked against the 15/13 character limits. The pack is installed so the server parses every function at load (a bad line is a load ERROR, which fails the build), but the tool sends each command through the console itself, following `function` lines (no macros), so every reply is checked: unknown commands, bad arguments, `Test failed`, `Could not set the block`, "No blocks were filled" and similar fail the build, as does any ERROR in the log. `forceload add x1 z1 x2 z2` lines make the tool wait until those chunks are loaded (and 3 s more for entities). At the end it disables the pack, removes the forceload, and saves.
- **Area:** forceloaded x -48..47, z -48..95 (54 chunks, about 4.6 MB on disk). Only those chunks and their generation border are saved. The paired beacons room sits high in the same chunks.
- **Copy and level.dat:** `level.dat`, `data/` and `dimensions/` are copied (not `session.lock`, `level.dat_old`, `players/`, `datapacks/`). `level.dat` (`Data.LevelName` "Bubba Test World", `GameType` 1, `allowCommands` 1, `file/builder` dropped from `DataPacks`) is edited with `tools/nbt.py` (also `python tools/nbt.py <file> [path]` to look inside any NBT file). 26.3 keeps game rules, weather and clocks in `data/minecraft/*.dat`, so the commands set them, not level.dat. `BUILD_INFO.txt` holds date, Minecraft version and mod jar names.
- **Verify:** a second server on a copy of the pristine world (no builder pack) runs `verify.mcfunction` (game rules via `execute store`, time 18000, clear weather, no woken undead, gear on sleepers, items in displays and chests, synthetic vs natural ore states, item frames, glider in the tower chest; the beacon yard pyramids and gem chest, the trap beacon's Poison gem and pig, both paired beacons (upright and `upside_down=true`) and the clear line between them, the totem chest, the spawn boxes, the wardrobe totem sign and Spawns on sign, and that placing the lit ring's torches woke nobody) plus an automatic `execute if block <pos> <state>` for every `setblock` and display command in the build (957 checks, 2026-11-16).
- **World rules (26.3 names):** `spawn_mobs`, `spawn_phantoms`, `spawn_patrols`, `spawn_wandering_traders`, `advance_time`, `advance_weather` all false; `respawn_radius 0`; `keep_inventory true` (so dying in the arena loses nothing); `command_block_output false` (the testing grounds' command block clocks would otherwise post to chat every tick); `time set midnight`; `weather clear`; `setworldspawn 0 -60 7 180 0` (facing north at the sign row). Invisible `minecraft:light[level=15]` every 6 blocks, 4 above the floor, over each station.
- **Techniques that matter:** sleepers are `setblock ... bubbas_reworked_mobs:<variant>_sleeper[facing=..,pose=..]{Items:[{Slot:<n>b,id:..,count:1}]}` (slots 0 main hand, 1 off hand, 2 head, 3 chest, 4 legs, 5 feet); command-placed blocks don't wake them (checked: no woken undead after the build). Displays use the mod's `display` command. Chests are `setblock ... chest[facing=..]{CustomName:"..",Items:[...]}` with item components in SNBT. Signs are waxed (`is_waxed:1b`) with SNBT text; lines are kept to 15 characters and bold titles to 13 so they fit. Item frames need `Pos` and `block_pos` in the summon NBT (26.3 checks the attached block is within 16 blocks of the entity while loading; without `Pos` it is at 0,0,0 and fails).

### Gem Testing Grounds (x -47..46, z 11..63, south of the hub)

- **Click signs (the technique):** a sign whose text lines carry `click_event:{action:"run_command",command:".."}` runs those commands, line by line, when right-clicked (any item in hand). 26.3 only runs them if the sign has `allow_op_features:1b` (otherwise the player sees "click actions disabled"); they run as the clicking player (`@s`) at permission level 2 from the sign's position, and their chat output goes nowhere. Click signs are left unwaxed (a waxed sign also plays the "can't edit" thunk on every click). Up to four commands per sign; more goes through a command block chain (below). Checked in the source: `SignBlock.useWithoutItem`, `SignBlockEntity.executeClickCommandsIfPresent`. Vanilla has nothing faster for armor: an armor stand swaps one slot per click into the hand, and the shelf block swaps hotbar items only.
- **Kit sign:** line 1 `item override entity @s armor.* with minecraft:air` (takes the worn armor off; deleted, not returned), line 2 `gems kit <effect> [material] [power]` (Infused Gems: a full worn set with 3 gems a piece, plus a sword with 2; Gem Power 6 is perfect), line 3 an equip sound. Gems whose test needs a tool also give it (owner: Haste needs mining tools, not a sword), in one `loot give @s loot {pools:[...]}` command with an inline loot table: Haste a netherite pickaxe, shovel and axe; Mining Fatigue and Conduit Power a netherite pickaxe; Luck a fishing rod (the equip sound moves to line 4). The verify step tries the take-off command on an armor stand; the screenshot test clicks the Speed sign as the player and checks the worn chestplate, then the Take off sign.

## Natural world

A second test world from normal generation, for seeing our things where the game puts them (owner, 2026-11-22). `python tools/build-naturalworld.py` (`--no-build`, `--keep`, `--seed N`) runs the same headless server on a normal world with seed 20261122. It finds a natural example of each with `/locate` (crypt yards, `monster_camp` from a plains, forest, desert, snowy plains and swamp biome so the kinds differ, the pillager outpost, the shipwreck, old-growth taiga for giant spiders) and the mod's own `ancient_fabricator locate` and `cairn locate`. It loads 49 blocks round each, lays a polished andesite platform at spawn with a click sign per example that teleports there (to the surface, or to the Fabricator's pad height), and saves. Then it keeps only fully generated chunks in the saved region files: `/locate` leaves about 10,000 part-generated chunks behind, about 85 % of the size, and they'd finish generating on a visit anyway. That takes the world from 51 MB to 7.5 MB (829 chunks). The found spots are written to `SPOTS.txt` in the world. Pristine copy: `testworlds/bubba-natural-world/`, **gitignored** (rebuilt from the seed, about 90 s), installed as the save "Bubba Natural World" by `tools/install-to-modrinth.ps1` when missing (`-ResetWorld` writes over it too). Time starts at morning and runs (owner, 2026-11-23), weather clear, nothing spawns on its own, so the builder places one persistent giant spider (`spider giant`, 5 blocks east of the taiga example) since giants only spawn in the dark.

Fixes (owner playtest, 2026-11-22):
- Every sign is a plain `tp @s X Y Z`. Each spot's surface height is read while its chunks are force-loaded at build time (a marker summoned `positioned over motion_blocking_no_leaves`). A heightmap lookup at click time did nothing, because the spot's chunks aren't loaded from spawn.
- Mob spawning is left on (no `spawn_mobs false`), so the world plays like a real one and the Fabricator runs. Time and weather stay frozen at build.
- The build server never pauses (`pause-when-empty-seconds=-1`).

Camp signs (2026-11-24): one per kind (skeleton, zombie, husk, stray, bogged), each from `/bubbas_reworked_mobs camp locate <kind>` (vanilla `/locate` gave the nearest camp of any kind, so signs led to the wrong kind). Each sign teleports 3 blocks south of the fire. After loading, the builder re-runs `camp locate <kind>` from each camp's own centre and fails the build unless it returns that same camp ("camp sign <kind>: camp at x z confirmed <kind>"; `camp list` stays empty headless, since registration needs a nearby player). Seed 20261122: skeleton 712 264, zombie 920 56, husk -1240 280, stray 232 2536, bogged -1704 1032.

Nether outpost and trader post signs (2026-11-24): "Nether outpost (piglins)" from `camp locate piglin` run in the Nether (its chunks force-loaded there, the sign teleports into the Nether 3 blocks south of the fire, Nether chunks pruned like overworld ones); "Trader post (wandering trader)" from `trader_post locate` (lands on the plaza centre, open ground between the stall and the fire). Seed 20261122: Nether outpost -1032 -213 (y 63), trader post -1672 -184 (y 63).

Not covered: spider nests (a feature in 17 % of cave chunks, not locatable; the flat world's Showcase has one) and crypt wealth (rolled per yard, so the three yards are whatever the seed gives).

## Screenshots

- **Run:** `./gradlew :testworldshots:runClientGameTest -PmilestoneTests` (milestone, test-lite: `specs/quality.md`; it is skipped without the flag) (Windows: `.\gradlew.bat`). About 50 s on the owner's PC with the mods already built (client start ~10 s, world open ~5 s, 140 screenshots (count from the last run, 2026-11-16)). Screenshots land in `mods/testworldshots/build/run/clientGameTest/screenshots/NNNN_<station>_<view>.png` (the folder is wiped at the start of each run). Look at them after any rebuild of the world or visible change to a station.
- **How:** `mods/testworldshots` is an internal harness mod (never published, `internal=true`) whose client game test loads the seven mods' built jars (`modsUnderTest` in its `build.gradle`; Gradle builds them first; Fabric Loader picks up every jar with a `fabric.mod.json` on the classpath) plus Fabric API. The game loads a private copy of the jars (`snapshotModJars`, a Sync into `mods/testworldshots/build/modsUnderTest/`), not the jars in each mod's `build/libs`: another agent rebuilding a mod during a tour rewrote its jar in place and the running game crashed ("ZipFile invalid LOC header") three runs in a row. Chosen over a hand-made Modrinth-style launch because it reuses Loom's client game test run, Fabric's screenshot API and CI's existing `runClientGameTest` job unchanged. Its server game test task is switched off.
- **The world:** the test copies `testworlds/bubba-test-world` (path passed as `-Dbubba.testworld`) into the run's `saves/` and opens the copy with Fabric's `TestWorldSaveImpl` (the public `worldBuilder()` only makes new worlds; this implementation class opens any save folder by name through `WorldOpenFlows`). The pristine folder is never opened.
- **Parts (owner: split for time):** the tour is split by station: `-PclientTests=cairns,creepers` photographs only those (each run still loads the world, about 40 s of overhead; the `cairns` part alone took 74 s with its 30 s wait). Parts: hub, preview (the hand-built cairn preview), creepers, cairns, graveyard, loot, arena, crafting, tower, gems, grounds (the testing grounds, beacons and warding). `-PmilestoneTests` alone runs all of them. Run only the parts whose stations changed.
- **Camera:** the player is switched to spectator (sleepers ignore spectators; no gravity; can sit inside a wall to read signs), the HUD is hidden (`gui.hud.toggle()`, the F1 key), and each shot is `tp` to an eye position with yaw and pitch computed to look at a target, then waits until chunks have rendered. Night and frozen time come from the world itself. Chest shots open the chest's menu on the server and take two pictures: the contents, and the first slot's tooltip (gems and effects). Shots and coordinates are in `TestWorldShots.java`; update them with the Layout above when a station moves. The tour also exercises the testing grounds: it clicks the wardrobe's Speed, Haste (checks the three tools) and Take off signs as the player (with a third-person picture in the set), flips the gallery lever and checks arrows fly, clicks Reset dummies and checks there are five again, and summons the Juggernaut for a picture; any failure fails the run. Beacons and Warding shots: `beacons_yard`, `beacons_yard_4layer_signs`, `beacons_gem_chest` (+ tooltip), `beacons_trap_zone`, `beacons_trap_poisoned`, `warding_bell_lane`, `warding_light_rings`, `warding_ground_signs`, `paired_room_beam`, `paired_room_signs`, `paired_room_sleepers`. The tour waits up to 300 ticks for the trap beacon to hurt the pig (Poison gems hurt steadily rather than giving the Poison effect) and fails if it doesn't.
