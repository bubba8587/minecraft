# Test world (spec)

A superflat world with a station for every playable feature, so the owner can try everything in one place (A3 ownerSteersByPlay).

## Pristine vs playable

- **Pristine:** `testworlds/bubba-test-world/` in the repo. Built only by `tools/build-testworld.py`, never opened in a game, committed to git. Holds a `BUILD_INFO.txt` with the date and the mod versions it was built with.
- **Playable:** `tools/install-to-modrinth.ps1` copies the pristine world into the Modrinth profile's `saves/` as "Bubba Test World". The owner plays that copy; nothing in it flows back to the repo.
  - The copy is made when it's missing. If the pristine world is newer than the copy, the script says so and leaves the copy alone; `-ResetWorld` writes over it with a fresh copy (owner: no old copies are kept; a reset also deletes any "Bubba Test World (old ...)" backups from earlier versions of the script).
  - The install also copies the owner's own settings, see `tools/sync-minecraft-settings.ps1`.

## How it's built

- A real headless Fabric server (Fabric's server launcher, Fabric API and the repo's built mods, the same downloads `tools/packtest.py` uses) creates a fresh superflat world and runs a builder datapack's function that places every station with commands, then saves and stops. Anything that fails is reported and fails the build.
- `level.dat` is then adjusted so it opens in singleplayer as intended: name "Bubba Test World", creative, cheats allowed.
- Rebuild whenever a feature changes what should be tested; the station list below is updated in the same change.

## World settings

Superflat (bedrock, dirt, grass), plains. Creative, cheats on. Time frozen at night (woken undead burn in daylight), clear weather locked, invisible light blocks so stations are lit. No random mob spawning (stations spawn what they need). Player spawn at the hub, facing the station signs.

## Stations

Each station has a sign naming it and saying what to try.

1. **Graveyard (Reworked Mobs):** rows of skeleton and zombie sleepers in every pose and facing, some with full gear, some with only a weapon, some empty-handed; a wool-walled pen to test that wool blocks noise; a dense crypt-like cluster to see chain waking.
2. **Loot on display:** every placement (ground, buried, wall, stuck) with a sword, bow, trident and a non-weapon item; a sleeper next to displays to see a woken undead grab one.
3. **Combat arena:** fenced, with chests holding a Smite V sword, a bow and arrows, armor sets, and a few sleepers to wake.
4. **Crafting Tweaks:** chests with every recipe's ingredients, a crafting table, blast furnace and smoker; Synthetic Diamond Ore next to natural deepslate diamond ore, labelled; Bamboo Paper next to plain paper in an item frame or chest.
5. **Glider tower:** a tall tower with a Glider, an elytra and firework rockets in a chest at the top, to compare flight.
6. **Infused Gems:** the whole gem workflow left to right (brew, enchant, socket, remove): base gems and effect items, potions in all three forms, brewing extras, a brewing stand, an enchanting table with 15 bookshelves, lapis and XP, a smithing table, a grindstone, armor of every material and weapons; a pen of mobs that never move (NoAI) to test weapon gems on.
7. **Gem Testing Grounds (Infused Gems; owner: "set up test world stuff for everything ... be creative"):** a wardrobe that puts on any gem's perfect set in one click; an arrow gallery and a live archer range (Ender, Breeze); drop pads (Wind Burst, Oozing, Slow Falling, Healing) and jump steps; a cobweb field (Weaving); a deep pool and a sky column (Water Breathing, Dolphin's Grace, Conduit Power, Levitation); a mob pen with spawn signs and target dummies with a health readout (weapon gems, undead inversion); villagers with fixed trades (Hero of the Village); a sculk hall with sleepers (Silence); a lava moat (Fire Resistance); a sealed dark room (Night Vision, Darkness, Blindness); a food bench (Hunger, Saturation); a mining wall (Haste, Mining Fatigue). Each station has kit signs for the gems it tests and, where damage matters, Survival/Creative signs.

## As built

- **Run:** `python tools/build-testworld.py` (builds all three mods with Gradle first; `--no-build` uses the current jars, `--verify-only` re-checks the pristine world, `--keep` keeps `build/testworld-server/` and `build/testworld-verify/` with a `console.log` of every reply, `--verbose` prints every command). About 30 s on the owner's PC with Gradle up to date (server start 7 s, build 13 s, verify ~8 s); the first run also downloads the Fabric launcher, Fabric API and the game libraries.
- **Server:** reuses `tools/packtest.py`'s download helpers and cache (`build/packtest/cache`, SHA-512 checked). `server.properties`: `level-type=minecraft:flat`, `generator-settings={"layers":[bedrock 1, dirt 2, grass_block 1],"biome":"minecraft:plains","lakes":false,"features":false}` (the 26.3 `FlatLevelGeneratorSettings` JSON; ground top at y=-61, stations stand on y=-60), `generate-structures=false`, `gamemode=creative`, `difficulty=normal` (peaceful would delete woken undead).
- **Builder datapack:** `testworlds/builder/` (namespace `bubba_testworld`, format 121; `tools/pack.py check` covers `testworlds/` packs). `build.mcfunction` calls one function per station: `setup`, `hub`, `crafting`, `tower`, `arena`, `loot`, `graveyard`, `gems`, `grounds` (which calls one `grounds_*` function per testing-grounds area). The `grounds_*` files are long and regular (one sign per gem); they were generated once by a throwaway script, so edit them directly. The pack is installed so the server parses every function at load (a bad line is a load ERROR, which fails the build), but the tool sends each command through the console itself, following `function` lines (no macros), so every reply is checked: unknown commands, bad arguments, `Test failed`, `Could not set the block`, "No blocks were filled" and similar fail the build, as does any ERROR in the log. `forceload add x1 z1 x2 z2` lines make the tool wait until those chunks are loaded (and 3 s more for entities). At the end it disables the pack, removes the forceload, and saves.
- **Area:** forceloaded x -48..47, z -48..63 (42 chunks, about 4.5 MB on disk). Only those chunks and their generation border are saved.
- **Copy and level.dat:** `level.dat`, `data/` and `dimensions/` are copied (not `session.lock`, `level.dat_old`, `players/`, `datapacks/`). `level.dat` (`Data.LevelName` "Bubba Test World", `GameType` 1, `allowCommands` 1, `file/builder` dropped from `DataPacks`) is edited with `tools/nbt.py` (also `python tools/nbt.py <file> [path]` to look inside any NBT file). 26.3 keeps game rules, weather and clocks in `data/minecraft/*.dat`, so the commands set them, not level.dat. `BUILD_INFO.txt` holds date, Minecraft version and mod jar names.
- **Verify:** a second server on a copy of the pristine world (no builder pack) runs `verify.mcfunction` (game rules via `execute store`, time 18000, clear weather, no woken undead, gear on sleepers, items in displays and chests, synthetic vs natural ore states, item frames, glider in the tower chest) plus an automatic `execute if block <pos> <state>` for every `setblock` and display command in the build.
- **World rules (26.3 names):** `spawn_mobs`, `spawn_phantoms`, `spawn_patrols`, `spawn_wandering_traders`, `advance_time`, `advance_weather` all false; `respawn_radius 0`; `keep_inventory true` (so dying in the arena loses nothing); `command_block_output false` (the testing grounds' command block clocks would otherwise post to chat every tick); `time set midnight`; `weather clear`; `setworldspawn 0 -60 7 180 0` (facing north at the sign row). Invisible `minecraft:light[level=15]` every 6 blocks, 4 above the floor, over each station.
- **Techniques that matter:** sleepers are `setblock ... bubbas_reworked_mobs:<variant>_sleeper[facing=..,pose=..]{Items:[{Slot:<n>b,id:..,count:1}]}` (slots 0 main hand, 1 off hand, 2 head, 3 chest, 4 legs, 5 feet); command-placed blocks don't wake them (checked: no woken undead after the build). Displays use the mod's `display` command. Chests are `setblock ... chest[facing=..]{CustomName:"..",Items:[...]}` with item components in SNBT. Signs are waxed (`is_waxed:1b`) with SNBT text; lines are kept to 15 characters and bold titles to 13 so they fit. Item frames need `Pos` and `block_pos` in the summon NBT (26.3 checks the attached block is within 16 blocks of the entity while loading; without `Pos` it is at 0,0,0 and fails).

### Gem Testing Grounds (x -47..46, z 11..63, south of the hub)

- **Click signs (the technique):** a sign whose text lines carry `click_event:{action:"run_command",command:".."}` runs those commands, line by line, when right-clicked (any item in hand). 26.3 only runs them if the sign has `allow_op_features:1b` (otherwise the player sees "click actions disabled"); they run as the clicking player (`@s`) at permission level 2 from the sign's position, and their chat output goes nowhere. Click signs are left unwaxed (a waxed sign also plays the "can't edit" thunk on every click). Up to four commands per sign; more goes through a command block chain (below). Checked in the source: `SignBlock.useWithoutItem`, `SignBlockEntity.executeClickCommandsIfPresent`. Vanilla has nothing faster for armor: an armor stand swaps one slot per click into the hand, and the shelf block swaps hotbar items only.
- **Kit sign:** line 1 `item override entity @s armor.* with minecraft:air` (takes the worn armor off; deleted, not returned), line 2 `gems kit <effect> [material]` (Infused Gems: a full worn set with 3 perfect gems a piece, plus a sword with 2), line 3 an equip sound. Gems whose test needs a tool also give it (owner: Haste needs mining tools, not a sword), in one `loot give @s loot {pools:[...]}` command with an inline loot table: Haste a netherite pickaxe, shovel and axe; Mining Fatigue and Conduit Power a netherite pickaxe; Luck a fishing rod (the equip sound moves to line 4). The verify step tries the take-off command on an armor stand; the screenshot test clicks the Speed sign as the player and checks the worn chestplate, then the Take off sign.
- **Command blocks:** 26.3's `command_blocks_work` game rule (default true) enables them, singleplayer or server. They sit under the floor at y -62. Arrow gallery: a lever on the floor at (-35, -60, 20) powers a repeating command block at (-35, -62, 20) whose chain (west to x -45) counts `#gallery tw_clock` and puts a redstone block behind each dispenser in turn (ticks 20, 40, 60: one arrow a second), refilling each to 64 arrows. ## Screenshots

- **Run:** `./gradlew :testworldshots:runClientGameTest` (Windows: `.\gradlew.bat`). About 50 s on the owner's PC with the mods already built (client start ~10 s, world open ~5 s, 124 screenshots ~45 s). Screenshots land in `mods/testworldshots/build/run/clientGameTest/screenshots/NNNN_<station>_<view>.png` (the folder is wiped at the start of each run). Look at them after any rebuild of the world or visible change to a station.
- **How:** `mods/testworldshots` is an internal harness mod (never published, `internal=true`) whose client game test loads the three mods' built jars (Gradle builds them first; Fabric Loader picks up every jar with a `fabric.mod.json` on the classpath) plus Fabric API. Chosen over a hand-made Modrinth-style launch because it reuses Loom's client game test run, Fabric's screenshot API and CI's existing `runClientGameTest` job unchanged. Its server game test task is switched off.
- **The world:** the test copies `testworlds/bubba-test-world` (path passed as `-Dbubba.testworld`) into the run's `saves/` and opens the copy with Fabric's `TestWorldSaveImpl` (the public `worldBuilder()` only makes new worlds; this implementation class opens any save folder by name through `WorldOpenFlows`). The pristine folder is never opened.
- **Camera:** the player is switched to spectator (sleepers ignore spectators; no gravity; can sit inside a wall to read signs), the HUD is hidden (`gui.hud.toggle()`, the F1 key), and each shot is `tp` to an eye position with yaw and pitch computed to look at a target, then waits until chunks have rendered. Night and frozen time come from the world itself. Chest shots open the chest's menu on the server and take two pictures: the contents, and the first slot's tooltip (gems and effects). Shots and coordinates are in `TestWorldShots.java`; update them with the Layout above when a station moves. The tour also exercises the testing grounds: it clicks the wardrobe's Speed, Haste (checks the three tools) and Take off signs as the player (with a third-person picture in the set), flips the gallery lever and checks arrows fly, and clicks Reset dummies and checks there are five again; any failure fails the run.
