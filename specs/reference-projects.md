# Reference projects

`mods/refmod` and `datapacks/refpack` exist to prove the toolchain and the knowledge base against the real game. They are never published.

`refmod` uses each major system the knowledge base describes, the way the notes say to, and has server game tests for each and a client game test with a screenshot. When it stops compiling or a test fails after a version bump, the notes for that system are stale.

`refpack` covers pack.mcmeta, function tags, plain and macro functions, command storage, recipes, predicates and advancements, with PackTest test functions for each, and must load clean on the vanilla server (`tools/packload.py`).

## refmod requirements

Mod id `refmod`, package `io.github.bubba8587.refmod`. One small feature per system, each named after the system so a reader can find it. Content IDs are under the `refmod` namespace. Display names come from `assets/refmod/lang/en_us.json`.

1. **Registration:** registry helper classes (`ModItems`, `ModBlocks`, `ModBlockEntities`, `ModEntities`, `ModComponents`, ...) registering with `Identifier`-based keys and `.setId(key)` on properties.
2. **Item + data component:** a `refmod:tally_stick` item whose custom data component (Codec + StreamCodec) counts uses; using it increments the count; the tooltip shows it.
3. **Tool via properties:** a `refmod:flint_hatchet` axe made the 26.3 way (`Item.Properties#axe(...)` or whatever the 26.3 source uses), so it strips logs through block transformers.
4. **Item component on an existing item:** make vanilla `minecraft:stick` a furnace fuel worth 50 ticks via the 26.3 component mechanism (`DefaultItemComponentEvents` or equivalent).
5. **Block + block state:** a `refmod:signal_lamp` block with a boolean `lit` state toggled by right-click, with blockstate, model and item model definition files.
6. **Block entity:** a `refmod:counter_block` whose block entity counts ticks, saves and loads through `ValueOutput`/`ValueInput`, and syncs to the client.
7. **Creative tab:** a `refmod` tab listing every refmod item.
8. **Entity:** a `refmod:pebble` thrown projectile, thrown by a `refmod:pebble` item, that deals 1 damage, with a client renderer (a thrown-item renderer is fine).
9. **Networking:** an S2C payload sent when the signal lamp toggles, which the client logs and shows in the action bar or a HUD element.
10. **Data attachment:** a persistent per-player attachment `refmod:lamp_toggles` counting how many lamps the player has toggled; survives death.
11. **Command:** `/refmod stats [player]` printing that player's attachment value; permission-gated for the optional argument.
12. **Event:** a server event that logs and counts block breaks of `refmod:signal_lamp`.
13. **Mixin:** one small MixinExtras mixin with a visible effect that a game test can check (for example, snowballs (or another simple vanilla behavior) change in a testable way).
14. **Recipes, loot, tags, lang, models via datagen:** use the Fabric data generation API (`fabric-datagen` entrypoint, `runDatagen`) to generate recipes for the new items, block loot tables, an item tag, and English lang entries. Generated files are committed.
15. **Client:** a key mapping that prints the client player's lamp toggle count from a synced copy, and a HUD element drawing a small text line while holding the tally stick.
16. **Game tests:** a server game test per behavior above that can run on a server (2, 3, 4, 5, 6, 8, 10, 11, 12, 13, 14's loot/recipe outputs), plus a client game test that places a signal lamp, holds the tally stick, and takes a screenshot, which the builder looks at.

The builder may add a class tweaker or extra mixins only when a requirement needs them. Textures: plain solid-color 16x16 PNGs generated by a script are fine for this internal mod (it is never published).
17. **No-new-blocks patterns (B15 fewNewBlocks):** (a) a `refmod:lantern_charm` item that, used on any block, spawns an `item_display` entity showing a custom item model on top of that block plus an `interaction` entity as its hitbox; right-clicking the hitbox removes both and drops the item. (b) Extra data on an existing vanilla block without a new block or block entity: right-clicking a vanilla `minecraft:barrel` with the tally stick stores a per-position counter in a chunk-level data attachment, which survives a chunk save/load. Game tests for both.
