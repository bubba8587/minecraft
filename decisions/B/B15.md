## Decision

Mods here add as few new blocks to the game as possible. Features are built from custom items, variants of existing blocks, and more depth on existing systems instead. Custom textures and models on existing blocks are allowed.

## Why

The owner's call, given in chat: "in order to serve forward compatibility/ease of updating/better player experience, we want to create as few new blocks as possible on top of the vanilla game. instead, we should lean on custom items, variants of existing blocks, and extending depth on existing systems."

## Consequences

- A new registered block needs a stated reason no item, existing-block variant or extension of an existing system could do the job, given to the owner before it is built.
- Allowed ways to get a new-looking block without registering one: resource-pack retextures and models of existing blocks, existing blocks' blockstate properties, display entities showing item models, and per-item looks through item model definitions and data components.
- Fewer registered blocks also means fewer things that break a world when a mod is removed, and fewer things to port on each release (B10 alwaysLatest).
- The internal reference mod's blocks exist to prove the block APIs and are not a precedent.

Reopen if: Minecraft adds truly data-driven custom blocks.
